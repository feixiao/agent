# AI Agent Harness 知识库与全景导读

> **术语勘误与说明**：
> 在 AI Agent 与基础软件工程领域，标准通用的行业术语为 **Harness**（中文通常译为 **控制线束**、**运行底座**、**测试底盘** 或 **工程底座**）。
> 开发者常因发音或联想（如 "Hardness" 难度/硬度，或 "Harmless" 安全无害性）而误拼为 `harmness`。
> 根目录曾为此建立兼容符号链接 `harmness -> harness`，已于 2026-11-17 按用户要求删除，统一使用 `harness/`。

## 一、 核心认知：什么是 Agent Harness？

在 AI 智能体体系中，有一个被工业界广泛验证的核心本质公式：

$$\text{Agent} = \text{Model（概率模型引擎）} + \text{Harness（确定性工程底盘）}$$

```
+--------------------------------------------------------------------------+
|                        大模型 / 概率引擎 (LLM / SLM)                       |
|           职责：语义理解、概率推理、发散思考（无状态、非确定性、高幻觉）            |
+-------------------------------------+------------------------------------+
                                      | Token 流 / 结构化意图
+-------------------------------------v------------------------------------+
|                         Harness (确定性工程底座 / 线束)                    |
|  [循环与状态机运行时]     [上下文治理与分层记忆]     [工具网关与权限沙箱]   |
|  [动态提示词装配管理]     [多模型路由与语法约束]     [安全护栏与输入输出过滤] |
+-------------------------------------+------------------------------------+
                                      | 确定性指令 / 生产系统契约
+-------------------------------------v------------------------------------+
|                   外部环境、底层系统 API、数据库与终端设备                  |
+--------------------------------------------------------------------------+
```

### 为什么大模型必须依赖 Harness？
1. **复合概率衰减法则（$Pass^k = p^k$）**：
   如果单步执行准确率为 $90\%$（$p = 0.9$），连续执行 10 步后系统的整体成功率仅有 $0.9^{10} \approx 34.8\%$。若无 Harness 提供循环检测、报错重试、状态回滚与确定性校验，复杂的长程智能体几乎必然崩溃。
2. **模型是无状态概率生成器**：
   大语言模型不保存任何历史，无法感知真实物理世界的约束，也无法主动安全地调用外部 API。
3. **Harness 的核心使命**：
   **用确定性的软件工程手段，对抗大模型概率推理的不确定性**，将模型发散的“思考”收敛为工业级稳定运行的“行动”。

## 三、 推荐学习路线

1. **第一步（树立系统观）**：阅读 [`01_core_concepts_and_components.md`](01_core_concepts_and_components.md)，搞清楚一个高可用 Agent Harness 内部必须包含哪些齿轮和链条；
2. **第二步（掌握场景差异）**：阅读 [`02_edge_vs_cloud_harness.md`](02_edge_vs_cloud_harness.md)，理解为什么手机/车机端不能照搬服务端的 Python 架构，以及端云混合（Hybrid Edge-Cloud）的通信形态；
3. **第三步（结合源码精读）**：阅读 [`03_open_source_projects_guide.md`](03_open_source_projects_guide.md)，挑选 1~2 个最契合你业务方向的开源项目（如服务端推荐精读 OpenHands，移动/端侧推荐精读 PalmClaw），对照文中的文件索引去 GitHub 深入看代码；
4. **第四步（上手调试原型）**：运行 `harness/examples/minimal_harness.py`，直观感受熔断机制、工具沙箱与上下文预算是如何运行的。
